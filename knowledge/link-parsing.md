# 链接 → 身份解析

用户贴平台链接时，用本文件解析。**解析不出就保留缺口，不猜站点、不猜 ID。**

## 能识别的形式（逐类核实后填写）

| 形式特征 | 提取出什么 | 用途 |
| --- | --- | --- |
| 详情页链接（含文件级 ID） | 文件级 ID | 定位任务、部署入参 |
| 实例/运行态链接（含实例标识） | 实例 ID + 文件级 ID | 诊断、巡检 |
| 引擎 UI 链接（含引擎侧数字段） | **作业唯一 ID**（不是引擎 jobId） | 引擎侧取证的入口 |

> 具体域名与路径形态**不写在这里**（脱敏要求）。使用者按自己的平台，把"这个形式的链接 → 提取哪一段 → 得到什么身份"补进上表，并记录核实时间。

## 三条硬规则

1. 链接里提取出的 ID 是**线索**，不是终态：拿到后必须回读核对（名称、项目、状态），对不上就报差异；
2. **禁止**把链接里的参数直接当接口入参（宪法第 8 条）——要重新按接口契约构造请求；
3. 引擎侧链接里的数字段是**作业唯一 ID**，不要当成引擎 jobId；jobId 要另外查身份接口拿。

## 与诊断流程的衔接

`runbook-diagnosis.md` 步骤 0 调用本文件；解析结果写进运行时对象（`rtd.py object set --source "link" …`），后续所有阶段复用这一份身份，不再重新解析链接。
