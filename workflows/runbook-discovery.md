# runbook-discovery：定位与状态快查

对应命令 `/rtd-discover`。只定位、只看状态，**不自动升级**成巡检或诊断。

## 步骤 0 · 输入归一

- 用户给的是对象名称、ID、实例、作业链接还是项目名？先归类。
- 给的是**平台链接** → 按 `knowledge/link-parsing.md` 提取身份；链接形式不在已核实清单里时**保留缺口**，不猜站点。
- 什么都给不出 → 追问。追问不到就停在这里，不要全项目乱搜。

## 步骤 1 · 唯一定位

- 已有唯一上下文 → 直接读详情，不重新全量搜索；
- 只有项目或名称 → 用运维侧搜索，**翻完所有页**。名字是模糊筛选，owner 是精确筛选；
- **首屏为空 ≠ 不存在**（反例库第 5 条）。

```
py -3 .rtd/engine/rtd.py object set --name "<对象名>" --source "ops search"
```

## 步骤 2 · 消歧

多候选时列出来：名称 / 文件级 ID / 来源 / owner / 状态，让用户选。

- 不默认第一个；
- 数字短 ID **不是**文件级 ID（`governance/identity-and-time.md`）；
- 同名不自动合并。

### 消歧前先查知识库（记忆层）

涉及表名/域时，先看知识库里有没有这张表的口径——**它比问用户快，也比猜准**：

```
py -3 .rtd/engine/rtd.py knowledge search --query "<表名或域>"
py -3 .rtd/engine/rtd.py knowledge read   --uri "<search 返回的 uri>"
```

- 命中了就把口径**原文**带进上下文，并注明来源 `uri`；
- 只认受管前缀（`knowledge.uri_prefix`）下的知识源，越界的 uri 会被引擎直接拒；
- 没命中就说"知识库里没有"，**不要凭印象补口径**——契约见 `knowledge/kb-index-contract.md`。

## 步骤 3 · 结构展开

- 拓扑查询拿到实例与任务 DAG；任务详情简式查询（有批量上限，超限分批）；只有需要 SQL / 执行计划 / 近期错误时才用详式；
- 分层保存：文件级 ID / 内部标识 / 实例 ID / 任务 ID，长 ID 保持字符串。

```
py -3 .rtd/engine/rtd.py object set --file-id "<文件级 ID>" --instance-id "<实例>" --version "<版本>"
```

## 步骤 4 · 状态回报（完成条件）

一句话交付，格式见 `governance/response-contracts.md` 的"状态快查"：

> 对象 X（来源：运维侧查询，读取时间 …）当前状态为 Y。此处只确认平台状态，未做引擎健康诊断。

## 失败分支

| 现象 | 处置 |
| --- | --- |
| 搜索接口报业务错 | 保留错误码与追踪 ID；**报错 ≠ 查无作业** |
| 权限不足 | 标明目标与缺口；读写权限分开判断，列表能过滤不是写权限的证明 |
| 链接解析不出身份 | 保留缺口，让用户补 ID，不猜 |
