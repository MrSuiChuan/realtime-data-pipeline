# runbook-tuning：单算子与运行参数调整

对应命令 `/rtd-tune`。规则源是 `version-effect-matrix.md`，本文件只写步骤。

## 1 · 澄清目标

"优化一下"→ **先诊断**（`runbook-diagnosis.md`），不自动改。要明确到：哪个任务 / 哪个节点（稳定 uid）/ 哪个属性 / 目标值是什么，才继续。

## 2 · 完整快照

取目标版本的完整结构 + 参数 + SQL 指纹，以及逻辑节点与物理算子的映射。已有有效目标计划就不强制重置——重置只生成预览，不持久化、不被部署消费。

## 3 · 只改目标字段

- 按稳定 ID / uid 精确定位**恰好一个**目标，**不按数组下标定位**；
- 保留全部非目标节点、连接与属性；
- "只改一个节点"是**意图**，请求仍须全量提交。

## 4 · 评估生效方式与风险

| 情况 | 结论 |
| --- | --- |
| 同链发散并发 | 必须完整重启（提前预告物理拆链）；热更新不适用 |
| 只改并发 | 保存执行计划 + 部署；保存 ≠ 生效 |
| 改运行参数 | 显式指定作用域；写后重新查询核实 |
| 缺关键字段 | 不保证部署成功——先说清，不"先试试" |

## 5 · 提案与确认

展示：最小差异 / 保存版本与部署版本 / SQL 保留证据 / 参数模式与范围 / 停顿与恢复点。

只授权保存就只保存。**没有并发保护（无 CAS）要如实说**：读后写之间存在竞态。

## 6 · 重读后保存

提交前刷新版本与状态；发现他人变更 → **停止旧提交、重新评审**。全量提交；比较返回的前后值，出现范围外差异就停止并报告。

## 7 · 部署与验证

显式消费目标版本 → 按 `limits` 轮询至终态 → 重读当前计划，核对：目标物理并发 / SQL 指纹 / 参数 / 非目标字段。需要引擎证据就**重新做身份映射**后查询，不复用重启前的 jobId。

## 8 · 观察效果

配置生效与性能收益**分别验收**；用同口径可比窗口。

"已部署，运行差异待核验"是**合法中间态**；只有确认"应生效而没生效"才判未生效；不循环重复同一个操作。

## 快照口径

平台配置计划 / 引擎 DAG / 物理计划**分开保留并标注来源**，不互相抄。
