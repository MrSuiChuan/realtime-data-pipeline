# runbook-dev：研发主流程

对应命令 `/rtd-dev`。三种进入方式：**有 SQL**（场景一）、**只有需求**（场景二）、**迁移**（走 `runbook-migration.md`）。

## 场景二前置（只有需求、没有 SQL）

| 步 | 做什么 | 出口 |
| --- | --- | --- |
| S2-1 | 摸清需求：指标 / 聚合粒度 / 过滤条件 / 时间语义，开放提问后归纳成清单让用户确认 | 用户确认的需求清单 |
| S2-2 | 发现来源元表：优先元表搜索并**按名称完全相等**确认；关键词不明确时可用资产检索辅助 | 每张来源表的已发布版本 |
| S2-3 | 理解表结构：取字段名 / 类型 / 描述 | 字段清单 |
| S2-4 | 设计输出表 schema，并查是否已存在：已发布 → 复用；只有开发版 → 复核后补提交发布；都没有 → 转 `runbook-metatable.md` | 输出表就绪 |
| S2-5 | 写 SQL：引用已发布元表名，SQL 里不写 DDL；用户确认后进主流程 | 用户确认的 SQL |

## 主流程

### 1 · 前置检查引用元表

1. 解析 SQL 里的 `项目.表`；
2. 每张表查**已发布**版本；搜索是模糊匹配，必须按名称完全相等才算命中；
3. 命中 → 可用；查不到 → 按角色分流：

| 角色 | 查不到时 |
| --- | --- |
| 来源表 | 先跨项目搜（排除项目名写错）→ 只有开发版就等上游发布（**不重建**）→ 全不可见优先查权限/未注册 → **只有用户明确说由本任务负责**时才建 |
| 输出表 | 二探（含开发版）；仍无 → 转元表流程 |

4. 证据落盘后设门：

```
py -3 .rtd/engine/rtd.py evidence add --kind refs_readback --from refs.json \
  --tool "<执行器名>" --command "<那条真实命令>"
py -3 .rtd/engine/rtd.py gate set --name refs_published --evidence <evidence-id>
py -3 .rtd/engine/rtd.py advance --phase build --reason "引用元表已确认发布"
```

### 2 · 项目定位（优先级递降）

1. CLI 的"请选择常用项目"协议响应 → 原样按序展示等用户选；
2. 从 SQL 反推项目名 → 用应用/项目检索验证 → 用户确认；
3. 已在应用列表 / 关键词搜索命中 / 用户直接给 ID（需验证可访问）；
4. **禁止**用"按名搜索任务"来证明项目存在。

### 3 · 目录与命名

- 目录必须来自真实查询；不存在时**确认后**创建；
- 命名规则校验；同项目查重（按名精确搜，命中数为 0 才可建）。

### 4 · 渲染与创建

1. 本地把 SQL 渲染成执行器要的结构（渲染方式按 `executors/contracts-cli.md`：官方渲染优先，本地脚本仅作降级）；
2. 渲染失败 → 改 SQL 或节点名，**不创建空对象**；
3. 创建后在运行时记录开发态长 ID 与详情页链接；
4. 把确认过的内容**原样**写进去，禁止写入后再独立转换出第二份。

### 5 · 编译（门控 `compile_ok`）

1. 发起编译，按 `limits.poll_*` 轮询到终态；
2. 失败按类分诊：

| 报错 | 处置 |
| --- | --- |
| 存储无权限 | 元表权限 ≠ 底层存储权限；按报错里 DDL 的连接器反推缺哪个存储的权限，去对应渠道申请 |
| 表不存在 | 回步骤 1 |
| 语法错 | 按报错定位改 SQL |
| 项目级权限 | 按平台渠道申请 |

3. 终态回执落证据 → 设门 → 推进到 `debug`。

### 6 · 调试（门控 `debug_confirmed`）

1. 选模式：链路验证用快速采样（线上采集），数据验证用构造输入（mock）；
2. 构造输入前先**只读**取服务端权威的输入表与字段；任一表 schema 缺失 → 退回快速采样，**不猜字段**；
3. 展示数据方案（采样量或 mock 构造）→ 用户确认 → 落 `debug_confirmed`；
4. 执行成功但**输出为空 ≠ 业务正确**：查流量、延迟、过滤与窗口，问用户是否扩大采样；
5. 迁移场景默认跳过本步。

### 7 · 配置（可选，门控 `sla_decided`）

- 调试通过后主动问是否配 SLA；跳过也要落 `sla_decided`（"跳过"是决策，不是空白）；
- 名称 / 集群 / 引擎 / 任务参数：读原值 → 展示原值/目标值/差异 → 确认 → 写入 → **逐字段回读**；
- 集群必须取真实候选（名称、资源水位、引擎版本），不猜集群名；
- 冷备优先条件全部满足才用冷备，否则热备；热备要为每张引用元表配主备映射，备表缺失 → 回元表流程。

### 8 · 提交（门控 `submit_ok`）

发起提交 → 轮询终态 → 成功后查**发布前校验状态**（提交成功不含发布信息，不得假定）→ 落证据 → 设门 → 推进到 `publish`。

### 9 · 发布（门控 `publish_ok`，独立确认）

```
py -3 .rtd/engine/rtd.py run start --kind publish --summary "发布 <对象>"
# …用户当次确认后执行发布…
py -3 .rtd/engine/rtd.py evidence add --kind publish_receipt --from publish.json --tool … --command "…"
py -3 .rtd/engine/rtd.py gate set --name publish_ok --evidence <id>
py -3 .rtd/engine/rtd.py run finish --run <run-id> --status 已验证 --trace <追踪 ID>
```

校验状态机：执行中 → 轮询；通过 → 回读展示待发布对象与影响 → 取当次确认；失败 → 修正后重新提交；**待人工确认 → 原样返回确认链接并停止**，人工完成后重查同一次校验，禁止盲重提。

### 10 · 启动（可选，高风险，走 `runbook-lifecycle.md`）

门控键 `start_confirmed` + `source_stopped` + `reset_time`（迁移场景），三项独立确认，缺一即停。

## 最终交付

各阶段状态 + 关键错误 + **本次真实获得的平台链接**。失败阶段如实返回，不虚构成功（`governance/response-contracts.md`）。
