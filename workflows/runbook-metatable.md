# runbook-metatable：元表管理

对应命令 `/rtd-metatable`。入口有两个：`runbook-dev.md` 步骤 1 的引用表缺失、S2-4 的输出表缺失。

## 0 · 先读通用生命周期

`datasources/metatable-lifecycle.md`（六步与五条关键约束）+ 目标类型码文件。**不要凭记忆填字段**。

## 1 · 发现数据源

按类型 / 项目 / 关键词搜索；精确匹配后记下数据源 ID 与"是否官方"标志。**不回显完整连接属性**（凭据与地址不进对话、不进报告）。

## 2 · 创建 / 编辑

- 展示完整定义（columns 是**全量**语义，必须完整展示）→ 确认 → 执行；
- 编辑是字段级合并，但 columns 一旦传入即全量替换——这一条要在确认里说清；
- 项目、数据源类型、父目录不可改；

## 3 · 提交（独立确认）

回读开发版 → 展示提交对象 + 定义 + 影响 → **单独确认**（与步骤 2 的确认相互独立）→ 提交。

| 情况 | 处置 |
| --- | --- |
| 权限失败并返回申请链接 | 原样交给用户，不代点 |
| 报物理表缺失 | 走下面的"回退建表" |
| 报类型不支持 | 引导到平台/数据源侧，**不按大类外推** |

**回退建表**（是提交失败的回退动作，不是前置固定步骤）：

1. 先核对当前 schema 支持的类型范围（`governance/capability-matrix.json`）；
2. 展示 DDL 模板 → 用户补全并确认 → 建表 → 回读；
3. 重新确认提交 → 重提。

## 4 · 发布校验

状态机同 `runbook-dev.md` 步骤 9：待人工确认 → 原样返回链接并停止，人工完成后**重查同一次校验**。

## 5 · 发布（独立确认）

校验通过 → 再次回读展示发布对象 + 定义 + 影响 → **单独确认** → 发布 → 轮询终态。

```
py -3 .rtd/engine/rtd.py run start --kind metatable-publish --summary "发布元表 <名称>"
```

## 与主流程的衔接

只有**全部引用元表都已发布**，才回 `runbook-dev.md` 继续；开发版存在不算就绪（宪法第 7 条）。
