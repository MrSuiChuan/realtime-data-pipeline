# runbook-migration：实时 SQL 任务迁移

对应命令 `/rtd-migrate`。默认**停在编译通过**；要不要提交、发布、启动，另问。

## 1 · 定位与预览源任务

- 按搜索/ID/链接定位源任务，先读摘要；
- 长内容分级读取：小（一次读完）/ 中（分段拉到临时文件，不在上下文里拼）/ 超长（先说清预期耗时再分段）；读完用**总行数字段**校验完整性；
- 权威标识是**任务名字段**（描述可能不一致）；
- 迁移者不是原 owner 时，读完主动提醒：底层存储权限可能导致编译失败（这是提前告知，不是事后解释）。

展示模板（逐项给，不要只说"找到了"）：任务名（第一行）/ 描述 / 项目 / owner / 链接 / SLA / 主备表 / 行数 / 摘要 → 用户二次确认。

## 2 · 迁移参数确认（一次问三项）

| 参数 | 默认 | 注意 |
| --- | --- | --- |
| 目标项目 | 同项目（推荐：避免跨项目权限与主备表限制） | 要改名就走项目定位流程 |
| 新名称 | `<原名>_migrated` | 仍要过命名规则与同项目查重 |
| 目录 | 目录搜索列真实目录供选 | 名称搜索通常不返回目录字段，**禁止用它反查目录** |

## 3 · 执行迁移（默认停在编译通过）

一条命令携带：全量分片 / 完整性校验 / 查重 / 创建 / 写入 / 编译（由执行器负责，Skill 不自己拼内容）。失败时用返回的阶段与目标 ID 续查，**不另起第二个目标**。

可选后续（按需追加，不默认做）：调试 → 提交 → SLA → 发布（发布要当次确认）。

```
py -3 .rtd/engine/rtd.py evidence add --kind compile_receipt --from compile.json --tool … --command "…"
py -3 .rtd/engine/rtd.py gate set --name compile_ok --evidence <id>
```

## 4 · 启动（迁移场景最严的门）

1. 启动动作自带提交 + 发布意图；只要包含启动，就**必须先**确认两件事：原任务已停止（这是**声明**，不是状态证明）+ 用户给出的恢复点时间；
2. 三项一次确认齐全时，才允许一条命令走完整链（`--start --source-stopped --reset-time <用户给的值> --yes`）；`--yes` 必须由用户在当次确认里明确授权；
3. 尚未确认源任务停止 → **最多迁到编译成功**，不加发布/启动，也不加"源已停"的声明；不能凭"准备停止/稍后停止"推断；
4. 跨会话独立启动：无法排除迁移来源时**重新问**，不沿用上一会话的隐含记忆。

```
py -3 .rtd/engine/rtd.py gate set --name source_stopped --user-confirm "<用户原话>"
py -3 .rtd/engine/rtd.py gate set --name reset_time --user-confirm "<用户原话>" --value "2026-09-20 10:00:00"
py -3 .rtd/engine/rtd.py gate set --name start_confirmed --user-confirm "<用户原话>"
```

引擎会拒绝把"看起来就是当前时间"的值当恢复点——自动填的时间不算确认。
