# runbook-lifecycle：启停、热更新、下线、取消部署

对应命令 `/rtd-lifecycle`。这是**改线上状态**的一类动作，门最严。

## 0 · 前置读取（三步，按序，缺一即停）

1. **依赖预检**：本次动作需要的三类工具（操作 / 配对进度 / 状态核验）齐备才允许提交——即使用户已经授权，工具不齐也停；
2. **身份与时间**：精确记下对象 / 实例 / 版本 / 时区（`governance/identity-and-time.md`）；
3. **版本生效矩阵**：确认本次动作的快照来源、保存版本、生效方式、验证项（`version-effect-matrix.md`）。

## 1 · 提交前检查

定位：文件级 / 来源 / 实例 / 任务 / owner / 当前状态。**未经确认不写入。**

展示六要素（缺一项就不问"要不要继续"）：

1. 对象与环境；
2. 动作与版本；
3. 恢复点或重置时间（用户给的，不是系统时间）；
4. SQL 与执行计划的影响面；
5. 预计停顿；
6. 风险与回退边界（有没有可回退点）。

## 2 · 操作选择

| 操作 | 要点 |
| --- | --- |
| 启动 | 部署动作用 START 类型；首次无检查点 → 重启式启动 + 用户确认的恢复点；恢复点的时间制有歧义就在**部署前**问清 |
| 重启 | 部署动作用 RESTART 类型；显式版本模式与启动模式；确认恢复点与 SQL 影响 |
| 热更新 | 仅限特定组合；同链发散并发不适用，须完整重启；不得承诺运行参数即时生效 |
| 停止 | 用户主动要求 + 二次确认；按任务形态决定是否传精确任务 ID；超时先查原状态，**不重复发起** |
| 下线 | 独立确认；必须有"停止成功"的证据；未停止不顺手停，先单独确认停止；进度查询可能推进清理，只在已授权流程里调 |
| 取消部署 | 仅特定任务类型；须有明确取消请求或流程失败后的取消授权；**取消 ≠ 停止**；不能绑定流程 ID 做条件取消 |

## 3 · 提交与追踪

```
py -3 .rtd/engine/rtd.py run start --kind lifecycle-start --summary "启动 <对象>（版本 vN）"
# …用户当次确认后执行…
py -3 .rtd/engine/rtd.py run finish --run <run-id> --status 已受理 --trace <追踪 ID>
```

- 只提交一次；保存受理状态 + 追踪 ID + 响应摘要；
- 轮询节奏按 `limits`；前台等待，不后台挂起；
- 超时或结果未定：保留追踪 ID，先查原进度与运行态/变更记录，**禁止编 ID 或自动重提**（反例库第 4 条）。

## 4 · 验收（终态成功 ≠ 完成）

| 操作 | 验收动作 |
| --- | --- |
| 部署/启动 | 重读拓扑与详情，核目标运行状态、实际版本、SQL 与计划、参数；热更新还要回读物理并发结构 |
| 停止 | 核**精确任务**已停止 |
| 下线 | 核目标下线状态；"搜索不到"不足以证明下线成功 |
| 部分节点 | 成败分别报告，一个成功不代表整体成功 |

## 5 · 记录

失败、重试、不透明的追踪 ID 全部落 `.rtd/_runs/`（引擎写，不手改）。
