# runbook-environment：执行器环境管理

对应命令 `/rtd-env`。环境管理**独立于业务调用**：不要求先定位作业；环境安装也**不授权**任何作业操作。

## 模式分派

| 用户说 | 模式 | 行为 |
| --- | --- | --- |
| 检查 / 看看环境 | check | 只查不装 |
| 安装 / 初始化 | install | 跳过已装的 |
| 更新 / 升级 | update | 仅当明确"有可用更新"时才升级 |

## 通用纪律

- 先 dry-run 预览，再执行；输出支持 JSON；退出码 0 = 就绪、2 = 有缺口；
- 只合并所需配置，**不重写整份宿主配置**；
- 不猜宿主路径、不索取凭据（认证由平台自己的 CLI/MCP 负责）；
- 装完刷新发现，并对**明确目标**做一次只读验证；没有明确目标时只能说"工具已发现，访问待验证"；
- 单组件失败继续其他组件，待审批 / 失败 / 部分安装分别保留。

## CLI 升级决策

CLI 缺命令、缺 flag、缺契约字段时：

1. 先问用户要不要升级；拒绝升级 → 按 `governance/executor-arbitration.md` 评估有界回退；
2. **不自动切换执行器**；
3. 版本号不是判据，**帮助正文才是**——未知子命令加帮助也可能返回 0。

## 三条状态别混

`配置存在` / `认证完成` / `当前会话可调用`（`governance/mcp-setup.md`）。只有第三种才算可用。

```
py -3 .rtd/engine/rtd.py env check --json
```

引擎不主动调平台：它只报"配置齐不齐、有没有探测记录"，认证与可调用要靠一次真实只读调用。

## 两条路（平台 / 开源）

执行器分两条路：**平台路径**（`cli` + 各域 MCP）与**开源路径**（`oss_flink` / `oss_paimon` / `oss_fluss`）。选一条配全即可开工：平台路径至少填全一个执行器，开源路径三段都要填全。只配一半时报的是"这条路缺哪个键"，不会拿另一条路的要求来指责你。
