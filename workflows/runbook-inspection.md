# runbook-inspection：健康巡检（单任务 / 批量）

对应命令 `/rtd-inspect`。**巡检只读**，不改任何线上状态。

## 单任务

### 1 · 范围与预算

默认窗口近 30 分钟。预算取 `.rtd/config.json` 的 `limits`（耗时、工具调用数、并发、外部节点、下钻数量上限）。**触顶即停**：已发出的调用自然结束，交一份**部分覆盖报告**，并写明哪部分没覆盖。

### 2 · 定位与"预期 vs 实落"核对

- 定位唯一确认：项目 / 文件级 ID / 来源 / 引擎身份；
- 拓扑展开全部实例与任务 DAG；详情核有效配置、生命周期、真实引擎地址；
- **预期集合**（部署配置、生命周期、已确认的运行要求）与**实际集合**（当前运行拓扑）独立对照：必要节点、主备、停用、缺席；
- 当前列表里没有 ≠ 原本就不需要运行；
- 阶段识别：连续流 / 窗口聚合 / 快照同步 / 回补 / 低流量分别识别；阶段没核实就标"条件性评分"；回补类不套连续流规则。

### 3 · 每轮必查上下游（一层）

真实实体去重；一层血缘可能指向存储实体，不冒充相邻作业。每个依赖记四项：状态 / 流量 / 错误 / 影响。

四种"没有结果"要分别记：未采集 / 能力未发现 / 接口无样本 / 权限不足。**缺项 ≠ 正常。**

给上下游预留约 1/3 的调用预算。

### 4 · 采样、事件与有限下钻

| 对象 | 规则 |
| --- | --- |
| 连续指标 | 核覆盖度与新鲜度；有洞不跨段、不补零；降采样不能证明"持续越线" |
| 事件 | 按 ID 去重；计划内与非计划分开；累计值只在同一 attempt 内取差 |
| 快照 | 按 ID 去重；区分周期 / 保存点 / 进行中 / 计划取消；一次成功不清除窗口失败率 |
| 资源 | 同一实例内核分子分母与单位；聚合值不当最差实例；内存多分支取最大、不相加 |
| 下钻 | 最多 2 个风险对象；日志带窗口 + 关键词 + 目标；**诊断中不生成火焰图、不自愈** |

### 5 · 映射与评分

Agent 采证 → 按输入契约映射成快照（工具字段不硬编码，缺项记 unknown 与原因）→ 本地脚本消费快照出报告（**脚本不碰网络**）→ 输出到项目外的**新目录**，不覆盖历史。

评分原则：缺证据不扣满也不判正常；暂评分单独标注；全无证据不虚构满分。**阈值是待校准的技术启发式，不是官方健康模型。**

### 6 · 历史与复检

- 历史比较只用可核验的旧快照，不靠聊天记忆；不兼容就不算分差；
- 两轮同现 ≠ 中间持续；缺采集不关闭风险；异常退出需要连续正常窗口才算恢复。

## 批量（用户明确项目 + 范围时）

按范围精确筛选 → 全页遍历 → 每个对象复用单任务流程；公共依赖证据只在**同窗口、同对象、同新鲜度**时可复用。

单个对象失败继续做其他；每个对象独立产出快照、结果与报告。

汇总报告含：范围 / 总数 / 优先异常 / 逐对象得分与完整性 / 共同上下游影响。**暂评分不参与平均，也不生成"项目综合分"。**

## 交付

按 `governance/response-contracts.md` 的巡检报告格式：五部分精简正文 + 取证附录 + 快照 + 评分；正常 / 异常 / 证据不足三种结果都必须交付。
