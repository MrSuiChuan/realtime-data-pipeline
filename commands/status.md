# rtd-status — 看当前阶段与门控缺口

```
py -3 .rtd/engine/rtd.py status --json
```

## 输出什么

| 字段 | 含义 |
| --- | --- |
| `object` | 当前对象：项目 / 文件级 ID / 实例 / 任务 ID（长 ID 保持字符串） |
| `phase` | 当前阶段（discover…start） |
| `gates` | 已满足的门控键与待满足的门控键 |
| `next_gap` | 下一个缺口，以及补它的动作 |
| `evidence_age` | 关键证据的采集时间（用于判断"还算不算数"） |
| `revision` | 状态文件版本，用于发现并发改动 |

## 三条读法

1. **只看机器写的键**：门控键由引擎按证据写入；如果某个键是由对话确认来的，它会带 `source=user_confirm` 标记，二者不混；
2. **证据有时效**：编译回执、发布校验、巡检快照都带时间。对象变了（新版本、新提交）旧证据自动失效，`next_gap` 会把它重新列出来；
3. **续跑先对账**：跨会话继续之前，先跑一次 `status` 再跑 `resume`；两者不一致时以平台真实状态为准，报告差异，不自动覆盖。

## 没有运行时的时候

项目里还没有 `.rtd/` 就直接说"未初始化，先跑 `/rtd-setup`"，不要凭空推断阶段。
