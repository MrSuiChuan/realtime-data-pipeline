# 执行器接入（MCP 与 CLI）

本文件是"要接哪些执行器、怎么接、接完怎么算数"的唯一来源。真实服务名与命令名**不在这里**，在项目级 `.rtd/config.json`。

## 一、职能代号（仓库里只用代号）

| 代号 | 职责 | 典型场景 |
| --- | --- | --- |
| `mcp_dev` | 任务全生命周期、迁移、目录、元表 | 研发、迁移、元表流程 |
| `mcp_ops` | 状态、拓扑、任务血缘、资源、指标、变更、参数、执行计划、启停 | 运维、巡检、诊断、生命周期 |
| `mcp_asset` | 项目与数据应用定位、资产检索、表知识、血缘 | 来源表发现、表结构理解 |
| `mcp_engine` | 引擎侧异常、日志、检查点、算子、运行态只读 + 火焰图采样 | 诊断、巡检取证 |
| `cli` | 平台命令行（默认执行器） | 研发与运维全域 |
| `storage.log_cli` / `storage.light_db_cli` | 存储侧取证工具 | 存储症状分支 |

## 二、按需接，不接全家桶

只接当前场景需要的服务。服务与场景的对应由根路由表派生；存储症状先确认连接器类型，再准备对应工具。

## 三、接入纪律

1. 按宿主的命令矩阵添加，**只合并所需配置**，不重写整份配置；
2. 不猜宿主路径、不索取凭据（认证由平台自己的 CLI/MCP 负责）；
3. 安装授权**不扩展**为生产变更授权；
4. 装完只做一次**针对明确目标**的只读请求验证；
5. 没有明确目标时只能说"工具已发现，访问待验证"；
6. 单个组件失败继续其余组件，结果分别保留（待审批 / 失败 / 部分安装）。

## 四、三种状态别混

| 状态 | 判据 |
| --- | --- |
| 配置存在 | 配置文件里有这一项 |
| 认证完成 | 一次只读请求返回了业务数据（不是 401/403） |
| 当前会话可调用 | 本次会话真的调到了它，且返回结构符合契约 |

只有第三种才算"可用"。

## 五、配置缺项时

报缺口并停：不猜命令名、不自动安装、不自动切到另一个执行器（切换规则见 `governance/executor-arbitration.md`）。
