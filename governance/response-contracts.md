# 输出契约

同一件事，Agent 该交什么、不该承诺什么，只在这里定义。工作流引用本文件，不重述。

## 状态快查

格式：**对象 + 状态 + 观测时间 + 证据来源**，一句话结束。

> 示例：对象 X（来源：运维侧查询，读取时间 12:03:41，追踪 ID …）当前状态为"已部署未启动"。此处只确认平台状态，未做引擎健康诊断。

不自动升级为巡检或诊断。用户要诊断会说。

## 巡检报告

五部分精简正文（正文约 800–1200 字）：关键发现 ≤3、优先建议 ≤3、依赖影响 ≤8、覆盖范围与缺口、结论；另附取证附录 + 快照 + 评分。

- 正常 / 异常 / 证据不足三种结果**都必须交付**，不许因为"看起来没事"就不出报告；
- 分数紧跟解释词；条件不完整时给**独立的"已观测风险暂评分"**并注明非完整分；
- 证据不足时不许虚构满分，也不许用默认值填空。

## 诊断报告

四要素：异常现象 / 根因 / 链路 / 修复方案。结论分四级：**已确认 / 较可能 / 已排除 / 未决**，每级附支持证据与反证。

根因未定也要交付，列明"待验证环节"和下一步要采什么证据；修复方案附目标、关键入参、调用顺序、进度追踪方式、生效验证步骤。

## 操作结果

只用这七个状态词：**未提交 / 已受理 / 进行中 / 失败 / 仅保存 / 已部署待验证 / 已验证**。

不承诺未观察到的成功。"接口返回成功"最多是"已受理"。

## 研发流程

每个阶段返回：阶段状态、关键错误、**本次真实获得的平台链接**。没拿到链接就明说没拿到。

## unknown 语义（宪法级，逐字引用）

未发现 ≠ 未安装；空列表 ≠ 无数据；查询失败 ≠ 零事件；运行中 ≠ 健康；
受理成功 ≠ 生效；部署成功 ≠ 目标生效；时间相关 ≠ 因果；用户认可 ≠ 证据。

## 表达纪律

- 分数、阈值、经验值必须带来源与校准状态（"技术启发式，未经真实故障窗口校准"）；
- 推断要标推断：`[推断]` 前缀 + 依据 + 反证；
- 报告先说结论，再说证据；不要用证据堆砌代替结论。
