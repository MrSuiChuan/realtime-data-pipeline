# 反例库

每条都是"看起来合理、其实是错的"推理。写代码、写提示词、写测试时都以此为准。

## 通用

| # | 错误推理 | 正确处理 |
| --- | --- | --- |
| 1 | 接口返回成功 = 已完成 | 成功最多是"已受理"，要回读终态 |
| 2 | 部署成功 = 目标已生效 | 重读运行态、实际版本、参数，必要时回读物理结构 |
| 3 | 任务 RUNNING = 健康 | RUNNING 只表示调度状态；有无数据、有没有反压要另查 |
| 4 | 超时了再点一次 | 先查原对象状态与变更记录；重发前必须确认上一次没成功 |
| 5 | 搜索首屏没结果 = 不存在 | 翻完分页；首屏空 ≠ 不存在 |
| 6 | 目录里没有数据 = 该作业没数据 | 目录存在 ≠ 有数据；空序列 ≠ 零值 |
| 7 | 血缘为空 = 没有上下游 | 一层血缘只覆盖已知引用，可能指向存储实体；空 ≠ 无 |
| 8 | 窗口内有过变更 = 变更导致了故障 | 时间相关 ≠ 因果；要给出链路与反证 |
| 9 | 权限不足 = 对象不存在 | 权限、注册、项目可见性是三件事，分别排查 |
| 10 | 用户认可了结论 = 可以按结论动手 | 诊断结论不构成写操作授权 |
| 11 | 安装同意了 = 后续都能用 | 配置存在、认证完成、当前会话可调用是三种状态 |
| 12 | 试点成功了 = 整批没问题 | 部分节点成败要分别报告，一个成功不代表整体成功 |
| 13 | 两轮巡检同现 = 中间一直存在 | 同现 ≠ 持续；缺采集不能关闭风险 |
| 14 | 用降采样曲线证明"一直超标" | 降采样不能证明持续越线；要覆盖度与新鲜度 |
| 15 | 用聚合值代表最差节点 | 聚合值不等于最差 TM；内存多分支取最大不相加 |
| 16 | 采样看到问题就能顺手改 | 采样授权不扩展为变更授权 |
| 17 | 报告里写"大概""应该是" | 按 `response-contracts.md`：已确认/较可能/已排除/未决 |

## 平台 CLI

| # | 错误推理 | 正确处理 |
| --- | --- | --- |
| 18 | 未知子命令加 `--help` 返回 0 = 该命令存在 | 保存帮助正文，grep 命令名与 flag 才算数 |
| 19 | 版本号更高 = 能力更全 | 版本号不是判据，帮助正文才是 |
| 20 | 省略 projectId 报错 = 调用失败 | 特定退出码 + 特定错误码是"选择常用项目"协议，按原顺序展示等用户选 |
| 21 | 搜索命中即可用 | 必须按名称完全相等才算命中，避免命中历史版本 |
| 22 | 配置更新返回 success = 已生效 | 逐字段回读核实 |
| 23 | 编译报存储无权限 → 去元表侧申请 | 元表权限 ≠ 底层存储权限；按报错里的建表 DDL 反推缺哪个存储的权限 |
| 24 | 重置执行计划成功 = 已生效 | 重置只生成预览，不持久化、不被部署消费 |
| 25 | 提交成功就等着跑 | 提交成功不含发布信息，必须另查发布前校验状态 |
| 26 | 校验待人工确认 → 重新提交一次 | 原样返回确认链接并停止；人工完成后**重查同一次校验**，不盲重提 |

## 平台 MCP

| # | 错误推理 | 正确处理 |
| --- | --- | --- |
| 27 | 运维侧 pipelineId 可以当部署入参 | 部署用开发态文件 ID；短 ID 只是识别用 |
| 28 | 详情查询默认会返回 SQL 与执行计划 | 只有详细模式返回；批量查询有数量上限，超限要分批 |
| 29 | 顶层字段就是待发布版本内容 | 带待发布版本时，顶层表示当前运行版本，待发布内容在专门嵌套字段 |
| 30 | 运行参数更新默认只影响当前版本 | `updateScope` 默认可能影响双层版本，必须按意图显式指定 |
| 31 | 写后返回的前后值 = 两份独立快照 | 写后重新查询核实；双层版本各自以原值合并 |
| 32 | 热更新后运行参数一定即时生效 | 不保证，不得承诺；同链发散并发不适用热更新，须完整重启 |
| 33 | 执行计划更新先读后写就没有竞态 | 没有 CAS，写前检查不能消除竞态；发现他人变更即停止旧提交 |
| 34 | 取消部署 = 停止任务 | 两者不同；取消也不能绑定流程 ID 做条件取消 |
| 35 | 用进度查询当无副作用的预检 | 下线类进度查询可能推进清理，只在已授权流程里调 |
| 36 | 工具描述提到的字段就发过去 | schema 未含的字段一律不发；缺真实值即停止，不填空串 |

## 引擎侧

| # | 错误推理 | 正确处理 |
| --- | --- | --- |
| 37 | 平台工具不好用，走引擎侧把作业停掉 | 引擎侧永久只读；平台失败就如实报告阻塞 |
| 38 | 重启后继续用旧 jobId 查指标 | jobId 随实例变化，重新做身份映射 |
| 39 | 拿引擎日志当全量事实 | 日志有截断与写入延迟；要带窗口、关键词与行数上限 |
| 40 | 快照成功一次就认为窗口内没失败过 | 一次成功不清除窗口失败率；FO/OOM 按 ID 去重、计划与非计划分开 |
