# 执行器仲裁

同一个动作可能有多个执行器能做（平台 CLI、平台各域 MCP、引擎只读 MCP）。本文件规定谁默认、什么时候可以换、换了之后锁在哪。

## 一、角色矩阵

| | 平台 CLI | 平台系 MCP（研发 / 运维 / 资产） | 引擎只读 MCP |
| --- | --- | --- | --- |
| 角色 | 默认执行器（研发 + 运维） | 没有 CLI 时的完整分支 / 有界回退目标 | 仅引擎侧只读取证 |
| 可写 | 是 | 是（限于该域范围） | **否，永久** |
| 替代关系 | ↔ 平台 MCP（受回退协议约束） | ↔ CLI（同上） | 不可替代，也不可被替代 |

执行器的**真实名称不写在仓库里**，从项目级 `.rtd/config.json` 的 `executors` 段读。配置缺项 = 该执行器不可用，报缺口并停。

## 二、默认链

1. CLI 存在 → 用 CLI；
2. CLI 不存在 → 说明安装会产生什么影响，征询同意；
3. 同意 → 按配置里的 `install_hint` 安装（`--yes` 只跳过安装交互，**不授权任何业务写**）→ 重新探测（不能只看安装退出码，要真的能列出版本/帮助）；
4. 拒绝 → 进入 MCP 分支，不再反复劝说；
5. 安装失败 → 返回真实错误并询问，**不默认切到 MCP**。

## 三、什么算"能力缺口"（三条同时成立才可以提议回退）

1. 已从**帮助正文**或稳定返回契约确认所需命令、flag 或必要返回字段**不存在**——不得凭版本号、退出码或某次空结果判断；"对象没有数据"不算缺口；
2. 当前会话真实 MCP schema 提供等价能力，且能拿到当前对象与必需 ID（MCP 没装时只能标"待安装并核验的候选"，装完必须核对真实 schema）；
3. 回退不会对可能已成功的写操作重复发起，也不会让"只能处理自己创建的对象"的工具接管 CLI 建的对象。

**排除清单**（不是缺口）：认证失败、网络错误、权限不足、参数错误、业务校验失败、服务端报错、超时、结果不确定、工具存在但调用失败。

## 四、回退单元

- **完整写流程回退**：只在 CLI 尚未对目标对象发起任何写操作时可用；切换后该对象的读写与轮询全部留在 MCP，不得中途切回；
- **独立能力单元回退**：MCP 必须完整覆盖"定位 → 输入校验 → 执行 → 异步轮询 → 终态核实 → 失败恢复"；只暴露一个近似触发工具不算完整；
- **进行中、终态未确认、结果不确定**的操作**锁死原执行器**，必须用原执行器和原对象 ID 核实；
- 执行器变更记录：回退范围、执行器、对象 ID、追踪 ID 全部落 `.rtd/_records/`。

## 五、六步流程

1. 展示缺口 + 拟切换的单元 + **不切**的部分；
2. MCP 服务未装时，按 `governance/mcp-setup.md` 只展示本单元所需服务，另取安装同意；
3. 核实真实 schema；无等价能力则停止并给人工路径，**不得**猜近似工具或跨执行器重试；
4. 展示已核实的等价能力与回退范围，等明确的回退同意（安装同意 ≠ 回退同意）；
5. 确认后完整读取对应执行器契约（`executors/`）；
6. 记录回退范围，锁定单元内所有操作。

拒绝回退时：保留已确认的参数，停止缺口操作，**不退回 CLI 盲试**。
