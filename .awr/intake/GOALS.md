# 目标：把实时数据开发工艺做成插件 {#goal-rtd-plugin status=active}

把实时数据开发工艺做成可安装的 Codex/Claude 插件 `realtime-data-plugin`：阶段状态机 + 硬门控 + 配置化执行器，包内零平台专有名，并给出可复现的验证证据。

**成功标准**

1. 包内对脱敏词表零命中，且这项检查在 CI 里是红的会拦（`tools/validate_plugin.py` 第 7 项）。
2. 阶段状态机能跑通链路：门控键只能由**平台回读证据**或**当次确认原话**产生，两者不可互相顶替；证据被改动后自检能发现。
3. hook 能拦住三类动作：直写证据/状态文件、无当次确认的 `--yes`、无当次确认的高风险动词。
4. 工作流与设计稿 `plan.md` §8.1–8.10 逐条对应，无遗漏。
5. 执行器名称与限额全部来自项目级 `.rtd/config.json`；配置缺项时**报缺口并停**，不猜、不自动装、不自动切换。
6. 验证记录区分"已验证"与"未验证"，不用推测内容填空。

**范围外（明确不做）**

- 不实现真实平台联调：本机没有可用的平台执行器，`config.json` 里只能填占位。
- 不搬运源包的专有 tool schema 快照、脚本与测试集：原件不可得，留作回填项，不伪造。

Provenance: 由 `plan.md`（脱敏设计稿）与本次构建的实际产物推导；目标措辞经用户确认（用户要求"自己写这个插件并进行测试"）。
