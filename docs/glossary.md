# 术语表

这个项目的文档里有一批自造词。它们不是装饰，每一个都对应一处**判据**。

| 词 | 含义 | 为什么不用更普通的说法 |
| --- | --- | --- |
| **阶段 / phase** | 状态机里的一步：定位 → 设计 → 研发 → 调试 → 配置 → 提交 → 发布 → 启动 | "步骤"太泛，这里每一步都有出口条件 |
| **门控键 / gate** | 阶段出口的开关。只有两种来源：**平台回读证据**或**当次确认原话** | "检查项"会让人以为是清单；这里是开关，不通过就走不下去 |
| **证据 / evidence** | 落盘的结构化回执（哈希可验），例如编译回执、发布回读 | 与"截图""说明"区分：证据能被机器验，说明不能 |
| **当次确认** | 用户针对这一次动作说的原话，带时间窗，用完即失效 | 与"同意过一次"区分——这个项目里确认**不传递** |
| **执行器 / executor** | 真正去动平台的通道：平台 CLI、各域 MCP、开源栈工具 | "工具"太泛；这里强调它与引擎的分工（引擎只读，执行器才写） |
| **引擎 / engine** | `engine/core.py` 与 `engine/rtd.py`：管状态、证据、记录，**不调用任何平台** | 与"脚本"区分：它是判据的唯一持有者 |
| **台账 / ledger** | 两本：工作项台账（`work-ledger.yaml`，AWR 权威源）与组件台账（`docs/oss-component-ledger.md`） | 一本记"谁在什么时候做了什么"，一本记"每个组件现在什么状态" |
| **tier（1 / 2 / 3）** | 组件验证程度：1 = 本机真跑过；2 = 已登记、有构件但没跑通；3 = 只登记角色与配置形状 | 用数字是为了让校验器能判定，也让"没跑过"无处藏 |
| **注册表 / registry** | `governance/oss-components.json`：组件的角色、构件、端口、内存与本地配方的唯一来源 | 与"配置"区分：注册表是仓库里的**知识**，配置是使用者机器上的**事实** |
| **能力矩阵** | `governance/capability-matrix.json`：每个执行器**已经验过什么**、已知缺口是什么 | 与注册表分工：注册表说"支持什么"，矩阵说"验过什么" |
| **项目级配置** | `.rtd/config.json`：真实命令名、地址、限额。**不进仓库** | 仓库里只有占位示例，这是脱敏的落点 |
| **缺口 / gap** | 配置不完整、构件缺失、能力未验证。报缺口时**必须给下一步** | 与"错误"区分：缺口是可预期的状态，不是异常 |
| **未验证 / 未跑通** | 明确的状态，不是修辞：表示"没有可复核的原始输出" | 这个项目宁可显得不完整，也不用推测内容填充 |
| **实验台 / lab** | `tools/oss_lab.py` 与它驱动的本地组件：装、起、停、探、冒烟 | 与"测试环境"区分：它按一次只起一个重型组件的纪律跑 |
| **冒烟 / smoke** | 一条最小的真跑：建表 → 写 N 行 → 读回 N 行，读数由注册表比对 | "演示"太弱；这里是判据 |
| **薄封装 CLI** | `tools/oss_cli.py`：把开源栈的取证包成一条命令 | "客户端"会让人以为它自带连接能力，其实它只拼命令与解析输出 |
| **宿主 / host** | 加载这个插件的一方：Claude Code 或 Codex | 插件本身不是程序，它靠宿主提供工具与 hook |
