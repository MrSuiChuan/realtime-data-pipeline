# 决策记录

这个项目里"为什么不那样做"的判断，集中记在这里。规则只有一条：**每条写清背景、决定、代价**——
代价那一栏是重点，没写代价的决策记录等于宣传。

新的决策往下面加一条即可（编号递增）；改动已有决策要写清为什么改。

## D1 账本放在仓库根，不放在 AWR 运行时目录

**背景**：AWR 接管后，工作项台账最初放在 `.awr/intake/work-ledger.yaml`。

**决定**：移到仓库根 `work-ledger.yaml`。

**代价**：运行时目录与源文件分家，看状态要同时看两处；换来的是 AWR **能写回**台账——
放在运行时目录里它只能读，状态只能手写，而手写的 `completed` 永远拿不到完成校验。

## D2 账本字段一律用单行标量

**背景**：多行块标量（`summary: |`）在 AWR 的 `yaml-ledger-v1` 改写器里写不回去——
它按行找映射冒号，块标量的续行没有冒号，会被当成坏映射。表现是**整份账本任何一次写回都失败**
（`quoted scalar marker mismatch` / `missing YAML mapping colon` / `YAML marker outside source` 三种报错）。

**决定**：账本里的字段一律单行；需要多段就用一句话说完。

**代价**：长摘要变成长句子，可读性略差；换来写回通道可用。这条不是风格偏好，是硬约束——
排查过程记在 `docs/awr-intake.md`。

## D3 许可证从 MIT 改为 Apache-2.0

**背景**：项目要按 Apache 项目的标准开源；MIT 不要求声明文件，也没有专利授权条款。

**决定**：改用 Apache-2.0（官方文本），补 `NOTICE`，给全部自研源码加逐文件许可头，
并把"许可头存在"加进静态校验。

**代价**：分发时要保留 `NOTICE`、源码要维护许可头；换来专利授权与更明确的声明义务。
这是**法律状态变更**，如果项目所有者更想保留 MIT，还原 `LICENSE` 与两份 `plugin.json` 即可。

## D4 组件知识在仓库，真实配置在项目侧

**背景**：插件要能公开分享，又要能对接具体平台与组件。

**决定**：仓库里只放**知识**——组件注册表（角色、构件、端口、配方）与执行器契约；
真实命令名、地址、账号、限额一律放项目侧 `.rtd/config.json`（gitignore，不进包）。

**代价**：使用者必须自己填一份配置才能跑；换来的是仓库里零平台专有名，可以直接公开。
静态校验第 7 项（脱敏扫描）与第 8 项（出站路由）就是这条决定的机器检查。

## D5 运行时零第三方依赖

**背景**：插件要装进别人的宿主机里跑。

**决定**：`engine/`、`hooks/`、`tools/` 只用 Python 标准库；测试用 pytest（开发期依赖，不分发）。

**代价**：有些事得自己写（比如 HTTP 请求用 `urllib` 而不是 `requests`）；换来的是
"装不上"这类第一现场消失，也省掉了依赖许可与版本漂移的维护。

## D6 验证锚定在代码提交，且不伪造

**背景**：AWR 的完成校验按提交 SHA 计算；每次提交都会让上一轮的验证"过期"。

**决定**：验证锚定在**代码提交**上（只写台账/报告的提交不重新锚定）；
没条件验证的工作项用 `work cancel` 收口并写明原因，**不用 complete 冒充通过**。

**代价**：每轮要重跑一次绑定，报告按 SHA 累积；换来的是"台账上的 completed 都有据可查"。
代价与操作步骤写在 `docs/reports/README.md`。
