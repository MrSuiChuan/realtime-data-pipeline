# 元表生命周期（通用骨架）

所有数据源类型共用这一份流程。类型差异见 `datasources/metatable-types.md`。

```
① 发现数据源（记录 ID 与官方标志，不回显完整连接属性）
 → ② 创建 / 编辑（展示完整定义并确认）
 → ③ 提交（物理表缺失时走"回退建表"，见下）
 → ④ 查发布校验（必须通过）
 → ⑤ 发布（再次回读展示定义与影响，另行确认）
 → ⑥ 轮询发布结果到终态
```

## 五条关键约束（原样保留，不许改写）

1. **官方/非官方数据源的字段差异很大**：先读对应类型文件，不要凭记忆填；
2. **编辑是字段级合并，但 columns 一旦传入即全量替换**；项目、数据源类型、父目录不可改；
3. **`published` 参数的语义**：不传/`true` 查已发布的生产版本，`false` 查开发版本；判断"这张表能不能被任务引用"**只认已发布版本命中**；
4. **物理表校验是通用的，建表范围看当前 schema**，触发靠提交报错倒推；当前明确支持建物理表的类型范围以 `governance/capability-matrix.json` 为准；
5. **校验通过才能发布。**

> 物理表建表是**提交失败的回退动作**，不是前置固定步骤。

## 与引擎的衔接

```
py -3 .rtd/engine/rtd.py run start --kind metatable --summary "创建/发布元表 <名称>"
py -3 .rtd/engine/rtd.py run finish --run <run-id> --status 已验证 --trace <追踪 ID>
```

发布完成后，引用表回读证据要在 `runbook-dev.md` 步骤 1 重新采集一次——**元表发布成功 ≠ 引用检查已经做过**。
