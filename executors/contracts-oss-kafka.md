# 开源栈执行器契约：Apache Kafka

Kafka 在插件里扮演**日志层**：实时任务的输入源、输出汇，以及"读回行数"这条证据的落脚点。
它在注册表里是 `launch_mode = service`，有独立进程与就绪探针。

## 配置形状

```json
{
  "executors": {
    "oss_kafka": {
      "home": "<Kafka 安装目录>",
      "bootstrap_servers": "<host:port>"
    }
  }
}
```

两个键都是必填：`home` 用来定位 bin 下的客户端工具，`bootstrap_servers` 是唯一连接入口。
占位符（`<…>`）不算已配置——这条判定与引擎、实验台、薄封装 CLI 用的是同一条规则。

## 使用契约

| 动作 | 约定 |
| --- | --- |
| 建 topic | 由执行器（不是模型）创建；分区数与副本因子来自项目配置，不写在脚本里 |
| 写入 | 走 console producer 或计算引擎的连接器；两者都要能被同一份配置驱动 |
| 读回（取证） | 读回必须用 `--from-beginning`，读到的**行数**是证据本身 |
| 作业侧读写 | 交给计算引擎的连接器（Flink / Spark），Kafka 侧只负责存储 |
| 巡检 | 只读：列 topic、看分区与消费滞后；不改分区、不删 topic |

## 判据不放松

**读回 0 行不是"通过"**。`tools/oss_lab.py smoke` 把"预期行数"当硬条件：
输出行数少于预期就是失败，与进程退出码无关——console 工具在消息没到齐时也可能退 0。

同理，**"命令失败"与"没有数据"必须分开记**：连接失败、topic 不存在、认证失败，
都记成失败并保留原始错误文本，不许写成"暂无数据"。

## 本地实验台

起停与冒烟由 `tools/oss_lab.py` 按 `governance/oss-components.json` 的配方驱动：
建 topic → 灌 N 行 → 从头上读回 N 行。重型组件一次只起一个，起第二个前先停前一个。
配方里的地址与路径全部来自项目配置，实验台自己不猜路径、不自动装。

## 已知缺口（登记在案）

| 缺口 | 事实 | 处置 |
| --- | --- | --- |
| KRaft 存储要先格式化 | 单机 KRaft 模式第一次启动前必须 `kafka-storage.sh format`，否则 broker 直接退 | 配方里做存在性判断后再格式化，不重复格式化已有数据目录 |
| 配置文件名随大版本变化 | 3.9 的 KRaft 配置在 `config/kraft/server.properties`，4.x 起只剩根目录下的一份 | 换大版本时按实际发行包核对，不照抄路径 |
| console consumer 的超时是空闲超时 | `--timeout-ms` 是"没有新消息就退出"，不是总时长 | 读回时必须配合 `--max-messages`，否则行数不稳定 |
| 样例数据目录 | 发行包自带一堆与本地实验无关的配置样例 | 不删、不改，实验只用自己的数据目录 |
| 自带守护模式在外部会话里活不下来 | `kafka-server-start.sh -daemon` 起的进程随启动它的那个会话被杀 | 配方用 `setsid nohup … &` 脱离会话，日志重定向到文件 |
| 进程存活判定会“自己匹配自己” | 用进程名匹配判断 broker 在不在跑时，启动器自己的命令行里就含这串字，于是永远判定为“已经在跑”，服务根本没起 | 判定改成探端口，不用会匹配到启动器命令行的模式 |
| 启动到可用之间有延迟 | broker 进程起来后还要注册完才接受连接 | 就绪探针按配置的超时窗口反复探，一次探不通不判失败 |
| 归档版本只在慢源上 | 3.9.2 这类归档版本只有归档站有，实测 13.8 KB/s，拉不动 | 优先选快镜像上还在的版本；版本与镜像可用性一起写进登记表 |
