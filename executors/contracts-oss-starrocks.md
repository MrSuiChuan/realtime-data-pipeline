# 开源栈执行器契约：StarRocks

StarRocks 在插件里扮演**实时分析 / 服务层**：任务产出的宽表落在这里，供即席查询与看板读。
注册表里是 `launch_mode = service`，本地方案是 FE 与 BE 各一个容器。

## 配置形状

```json
{
  "executors": {
    "oss_starrocks": {
      "fe_image": "<FE 镜像>",
      "be_image": "<BE 镜像>",
      "mysql_endpoint": "<host:查询端口>",
      "container_prefix": "<容器名前缀>",
      "network": "<容器网络>"
    }
  }
}
```

判定"已配置"的关键键是镜像与查询入口：**没有镜像就没有组件**。

## 为什么走容器而不是安装包

这不是偏好，是**唯一可达的通道**。实测：

| 通道 | 结果 |
| --- | --- |
| GitHub Release 的 `assets` | 空（逐个版本查过，官方不挂二进制） |
| 官方 CDN（releases.starrocks.io） | 403 |
| Apache 镜像站 | 该项目不是 ASF 项目，镜像站没有 |
| 云厂商镜像 | 返回的是网页而不是文件 |
| **容器镜像** | 可达，且本机已有 3.3.9 的 FE 与 BE |

结论写在这里，避免下一个人把上面五条再试一遍。

## 使用契约

| 动作 | 约定 |
| --- | --- |
| 起 | FE 与 BE 各一个容器；FE 的查询端口发布到宿主机 |
| 等就绪 | **查询端口能连不等于可用**：必须等 BE 的心跳为真，才算集群可用 |
| 建库建表 | 由执行器执行；分布键、分桶与副本数来自工单，仓库里只给冒烟用的最小写法 |
| 取证 | 读回行数：写 N 行、再从同一张表读回，行数一致才算过 |
| 巡检 | 只读系统表；不做 tablet 修复、不做 schema 变更 |

## 已知缺口（实测）

| 缺口 | 事实 | 处置 |
| --- | --- | --- |
| 容器默认命令是 bash | 镜像的 CMD 是 `/bin/bash`，用普通分离方式起会立刻退出 | 必须用交互式分离方式起容器 |
| BE 要显式声明网段 | 容器里既有回环又有网卡，不指定会注册成错地址，FE 一直显示没有可用 BE | 起 BE 时写入它的对外网段配置 |
| 就绪要等心跳 | 查询端口先开，此时 BE 还没注册，建表会因为没有可用 BE 而失败 | 就绪判定等到心跳为真；冒烟前也先确认 BE 可用 |
| 注册是幂等的反面 | 重复注册同一个 BE 会报错 | 起之前先清掉同名容器，避免半旧状态 |
| 内存 | FE 与 BE 合计约 4 GB 上下 | 与其它重型组件互斥，一次只起一个 |
