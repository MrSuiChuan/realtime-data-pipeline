# 开源栈执行器契约：ClickHouse

ClickHouse 在插件里扮演**实时分析/服务层**：任务产出的宽表落在这里，供即席查询与看板读。
注册表里它是 `launch_mode = service`，就绪探针是原生 TCP 端口。

## 配置形状

```json
{
  "executors": {
    "oss_clickhouse": {
      "home": "<ClickHouse 安装目录（解包后的那个）>",
      "tcp_endpoint": "<host:port>"
    }
  }
}
```

`home` 用来定位单二进制，`tcp_endpoint` 是连接与就绪判定共用的入口。

## 使用契约

| 动作 | 约定 |
| --- | --- |
| 启动 | 配置由实验侧生成（见下），数据目录、临时目录、端口都在配置里，不写死 |
| 建库建表 | 由执行器执行；引擎类型与排序键来自工单，不在配方里写死 |
| 写 | 走客户端一条多语句查询；语句失败与"写进去 0 行"要分开报 |
| 取证 | **读回行数**：建表后写 N 行、再从同一张表读回，行数一致才算过 |
| 巡检 | 只读查询（系统表）；不做任何后台合并或表结构变更 |

## 已知缺口（实测）

| 缺口 | 事实 | 处置 |
| --- | --- | --- |
| 最小配置缺三段 | 只给 `path`/端口时，启动在 `setDefaultProfileName` 处直接失败 | 配置里必须自带 `profiles` / `quotas` / `users` 三段，否则起不来 |
| 停止要按 PID | 端口与进程名都可能撞车（别的组件也在跑） | 从数据目录的 `status` 文件取 PID 再停；不要用进程名匹配 |
| 单二进制体积 | 解包后的可执行文件约 500 MB，压缩包约 138 MB | 拉之前先看镜像速度；归档版本可能只在慢源上 |
